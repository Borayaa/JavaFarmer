@code_tooltip_South = The down direction on the screen. Unless you turn your screen around.
@code_tooltip_West = The left direction on the screen. Unless you turn your screen around.
@code_tooltip_not = Rust writes `!` instead of `not`: `!true` is `false` and `!false` is `true`.
@code_tooltip_and = Rust writes `&&` instead of `and`: `a && b` is `true` only if both `a` and `b` are `true`. If `a` is `false`, `b` is not evaluated at all.
@code_tooltip_or = Rust writes `||` instead of `or`: `a || b` is `true` if at least one of `a` and `b` is `true`. If `a` is `true`, `b` is not evaluated at all.
@code_tooltip_return = Used to leave a function and give back a value: `return value;` (or just `return;`). The last expression of a function, written without `;`, is its value too.
@code_tooltip_pass = Rust has no `pass`. An empty block `{ }` is allowed.
@code_tooltip_true = A boolean value (`bool`) that is always true.
@code_tooltip_false = A boolean value (`bool`) that is always false.
@code_tooltip_fn = Declares a function: `fn name(a: i32, b: f64) -> i32 { ... }`. Every parameter needs a type, and `-> T` is the type of the value it returns (leave it out if it returns nothing). Another window can only use it if it is `pub fn`.
@code_tooltip_let = Declares a variable: `let x = 5;`. A `let` variable can't be changed; write `let mut x = 5;` for a variable you want to change. `let (a, b) = pair;` takes a tuple apart.
@code_tooltip_mut = Makes a variable changeable: `let mut count = 0;` and then `count += 1;`. A function that changes a collection takes it as `&mut`: `fn fill(v: &mut Vec<i32>)`.
@code_tooltip_const = Declares a constant at the top of a file: `const SIZE: i32 = 6;`. It can never change, and its type must be written.
@code_tooltip_static = Declares a global value at the top of a file: `static LIMIT: i32 = 10;`. A `static mut` can be changed, but every read and write of it must be inside `unsafe { ... }`. Passing values as parameters is usually simpler.
@code_tooltip_loop = Repeats its block forever, until a `break` (or `return`) leaves it.
@code_tooltip_match = Chooses a branch depending on a value: `match x { 1 => a(), 2 | 3 => b(), _ => c(), }`. `_` matches everything else. It also takes apart an `Option`: `Some(e) => ...` and `None => ...`.
@code_tooltip_mod = `mod utils;` makes the code window named utils a module of this file. Use its `pub` items as `utils::f()`, or bring them in with `use utils::f;`.
@code_tooltip_use = Brings names into scope. `use farm::*;` gives you the game's functions and constants (every program starts with it), `use std::collections::{HashMap, HashSet};` gives you maps and sets, and `use utils::f;` a function of another code window.
@code_tooltip_pub = Makes an item visible to other code windows: `pub fn f()`, `pub const N: i32 = 3;`. Without `pub` an item is private to its window.
@code_tooltip_unsafe = `unsafe { ... }` is needed around every read or write of a `static mut` variable.
@code_tooltip_as = Converts a number to another type: `x as f64`, `f as i32` (drops the decimals), `i as usize` to use an `i32` as an index.
@code_tooltip_in = Part of a for loop: `for x in collection` or `for i in 0..n`.
@code_tooltip_keyword_move = `move` before a closure (`move || { ... }`) makes the closure keep its own copy of the variables it uses. In JavaFarmer every closure works like that, with or without `move`: it can read the variables around it, but it cannot assign them.
The game's `move()` function is called `move_to()` in Rust.

example:
`let row = get_pos_y();
spawn_drone(move || {
	println!("{}", row);
});`
@code_tooltip_Some = `Some(value)` is an `Option` that holds a value. Check for it with `if let Some(e) = get_entity_type() { ... }` or compare with `== Some(Entity::Bush)`.
@code_tooltip_Option = `Option<T>` is a value that may be missing: `Some(value)` or `None`. The game's functions that can give "no value" return one, like `get_entity_type()` and `get_companion()`. Use `if let Some(x) = ...`, `.is_some()`, `.is_none()` or `.unwrap()` (an error if it is `None`).
@code_tooltip_Vec = `Vec<T>` is a list of values of type `T`: `Vec::new()` or `Vec::from([1, 2, 3])`. `v.push(x)`, `v.pop()`, `v.len()`, `v[i]` (the index is a `usize`).
@code_tooltip_HashMap = `HashMap<K, V>` is a dictionary from keys of type `K` to values of type `V`: `HashMap::new()`, `m.insert(k, v)`, `m.get(&k)` (an `Option`), `m[&k]`, `m.contains_key(&k)`. Needs `use std::collections::HashMap;`.
@code_tooltip_HashSet = `HashSet<T>` is a set of values: `HashSet::new()`, `s.insert(x)`, `s.contains(&x)`, `s.remove(&x)`. Needs `use std::collections::HashSet;`.
@code_tooltip_String = A piece of text that you own, like `String::from("hello")` or `x.to_string()`. A literal `"hello"` is a `&str`. `format!("{} {}", a, b)` builds a `String`.
@code_tooltip_i32 = A whole number like `5` or `-3`. Positions and the world size are `i32`.
@code_tooltip_f64 = A number with a decimal point like `0.25`. `num_items()`, `get_water()`, `get_time()` and `random()` return `f64`, so compare them with `1.0`, not `1`.
@code_tooltip_bool = `true` or `false`. Conditions of `if` and `while` must be a `bool`.
@code_tooltip_usize = A whole number that can't be negative, used for indexes and lengths: `v[i as usize]`, `v.len()`.
