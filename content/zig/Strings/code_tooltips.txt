@code_tooltip_range = Zig has no range function. A for loop counts over a range `start..end`: `for (0..n) |i| { }` counts from `start` up to (but not including) `end`. Both ends are `usize` numbers.

takes `1` tick to start the loop.

example:
`for (0..10) |i| {
    std.debug.print("{d}\n", .{i});
}

    std.debug.print("{d}\n", .{i});
}

var n: i32 = 10;
while (n > 0) : (n -= 1) {
    std.debug.print("{d}\n", .{n});
}`

@code_tooltip_pop = `list.pop()` or `list.orderedRemove(i)`

_ = list.orderedRemove(0);`

@code_tooltip_for = A loop. `for (0..n) |i| { }` counts from `0` to `n - 1`. `for (items) |x| { }` runs once for every element of an array or slice, `for (list.items) |x| { }` for a `std.ArrayList` (a "foreach" loop). `for (items, 0..) |x, i| { }` gives the index too.
@code_tooltip_while = Loops as long as the condition is `true`: `while (c) { }`. `while (true) { }` loops forever (until `break`). `while (c) : (i += 1) { }` runs `i += 1` after every round, also after `continue`.
@code_tooltip_def = Zig declares functions with `fn`, and every parameter needs a type: `farm.double(n: i32) i32 { return n * 2; }`. The return type comes after the parameters (`void` if it returns nothing).
@code_tooltip_True = Zig writes `true` (lowercase): a boolean value that is always true.
@code_tooltip_False = Zig writes `false` (lowercase): a boolean value that is always false.
@code_tooltip_if = Executes code if the condition is `true`: `if (c) { } else { }`. The condition must be a `bool`: Zig has no "truthy" values, so write `if (list.items.len > 0)`. `if (opt) |v| { }` runs only if the optional `opt` is not `null`, with its value as `v`.
@code_tooltip_else = Executes code if the previous `if` condition was `false`. `else if (c) { }` checks another condition.
@code_tooltip_elif = Zig writes `else if (condition)`, which does the same thing as:
`else {
    if (condition) {
        ...
    }
}`
@code_tooltip_None = Zig writes `null`: the value of an optional (`?T`) that holds nothing. The game's functions that can give "no value" return an optional, like `farm.getEntityType()`.
@code_tooltip_continue = Immediately continue with the next loop iteration. If there are nested loops, this will always affect the innermost loop.
@code_tooltip_break = Break out of a loop and continue executing the statements after the loop. If there are nested loops, this will always affect the innermost loop.
@code_tooltip_North = The up direction on the screen. Unless you turn your screen around. In Zig `farm.Direction.North`, or `.North` where Zig knows the type.
@code_tooltip_East = The right direction on the screen. Unless you turn your screen around. In Zig `farm.Direction.East`, or `.East` where Zig knows the type.
@code_tooltip_South = The down direction on the screen. Unless you turn your screen around. In Zig `farm.Direction.South`, or `.South` where Zig knows the type.
@code_tooltip_West = The left direction on the screen. Unless you turn your screen around. In Zig `farm.Direction.West`, or `.West` where Zig knows the type.
@code_tooltip_not = Zig writes `!` instead of not: `!true` is `false` and `!false` is `true`.
@code_tooltip_and = `a and b` is `true` only if both `a` and `b` are `true`. Both must be `bool` values (Zig has no "truthy" values). If `a` is `false`, `b` is not evaluated at all.
@code_tooltip_or = `a or b` is `true` if at least one of `a` and `b` is `true`. Both must be `bool` values (Zig has no "truthy" values). If `a` is `true`, `b` is not evaluated at all.
@code_tooltip_return = Used to leave a function and give back a value: `return value;` (or just `return;` in a `void` function). The type of the value is written after the parameters: `farm.double(n: i32) i32`.
@code_tooltip_pass = Zig needs no placeholder statement: an empty block `{}` is allowed and does nothing, like `while (!farm.canHarvest()) {}`.
@code_tooltip_true = A boolean value (`bool`) that is always true.
@code_tooltip_false = A boolean value (`bool`) that is always false.
@code_tooltip_null = The value of an optional (`?T`) that holds nothing. `farm.getEntityType()` gives `null` on an empty tile. Check it with `if (x) |v| { }` or `x == null`, give a default with `x orelse default`, or unwrap it with `x.?` (an error if it is `null`).

example:
`if (farm.getEntityType() == null) {
    _ = farm.plant(.Bush);

@code_tooltip_fn = Declares a function: `farm.name(a: i32, dir: farm.Direction) bool { ... }`. Every parameter needs a type, and the return type comes after the parameters (`void` if it returns nothing). Functions are written in camelCase. Another code window can only use it if it is `pub fn`.

example:
`fn doTwoFlips() void {
    farm.doAFlip();
    farm.doAFlip();

@code_tooltip_pub = Makes a declaration visible to other code windows: `pub fn goTo(x: usize, y: usize) void`, `pub var moves: i32 = 0;`. Without `pub` it is private to its window. The entry point is always `pub fn main() void`.
@code_tooltip_const = Declares a name whose value never changes: `const size = farm.getWorldSize();`. Zig wants `const` for every variable that you never change.

@code_tooltip_var = Declares a variable that can be changed: `var count: i32 = 0;` and then `count += 1;`. A number variable needs a type (`var x = 0;` is an error), and a `var` that is never changed is an error too: use `const` then.

example:
`var count: i32 = 0;
count += 1;`
@code_tooltip_void = The type of "nothing": a function that returns no value is declared `farm.f() void`. A set is a map with `void` values: `std.AutoHashMap(i32, void)`, filled with `put(x, {})`.
@code_tooltip_orelse = Gives a default value if an optional is `null`: `const n = m.get(key) orelse 0;`. `const e = farm.getEntityType() orelse return;` leaves the function if there is no value; in a loop `orelse continue` and `orelse break` work too.

@code_tooltip_try = Calls something that can fail (an error union, like `list.append(farm.allocator, x)`) and leaves the function with the error if it fails. A function that uses `try` returns `!void` (or `!T`), like `pub fn main() !void`.

example:

@code_tooltip_catch = Handles the error of a call that can fail. `list.append(farm.allocator, x) catch unreachable;` says that the call never fails here (the game never runs out of memory), so the function doesn't need `!void`. JavaFarmer does not support `catch |err|`.

@code_tooltip_defer = Runs a statement when the current block ends. It is used to free a list or a map right after creating it: `defer list.deinit(farm.allocator);` or `defer m.deinit();`. JavaFarmer supports `defer` only for `deinit` (the game frees memory by itself).
