# Mods menu & content extensions (design spec)

Read docs/SPEC-v2.md §5 first, and the research report /tmp/claude-1000/-home-boraya-01-Personal-02-Boraya-05-Code-farmer/093a3f76-1940-4716-8bcd-c9c28e2c3c69/scratchpad/research/game-extension-points.md
(copy it to docs/research/game-extension-points.md — it is the engineering reference for every hook below).

## 1. Player-facing behaviour
- Title page and pause menu (same `Menu` object) get a **Mods** button (cloned OptionsButton, label "Mods"; reflow the
  buttons so nothing overlaps). It opens a **Mods panel** (cloned Options panel, only our rows + Back):
  1. **Programming language**: cycle Python / Java / C / C++ / C# / Rust / Zig / JavaScript / R. Changing it asks
     "Convert this save's code to <lang>? (a backup is kept)" via `warningPopup`, then converts, saves, reloads the scene.
  2. **Extensions**: one row per extension: name, one-line description, Enabled/Disabled. Changing a toggle asks to apply
     (save + reload scene, SPEC research §4.4). Default: all extensions **Disabled**.
- With an extension disabled the game is exactly the base game + language mod: no extension unlocks, items, builtins,
  docs pages or timers. Turning it on adds them; progress (extension unlocks bought, extension items owned, task state)
  is stored per save in `Saves/<save>/javafarmer.json` and survives being turned off and on.
- Steam stats/achievements: extension items use `trackStats = false`; leaderboard uploads stay blocked.

## 2. Framework (src/JavaFarmer.Plugin/Extensions/)
```csharp
interface IExtension {
  string Id { get; }                 // "cybersecurity", "ai_ml"
  string DisplayName { get; }        // "Cybersecurity", "AI / ML"
  string Description { get; }        // one line for the Mods panel
  IReadOnlyList<ItemDef> Items { get; }        // registered ALWAYS at item-id time (enabled=false when off)
  IReadOnlyList<UnlockDef> Unlocks { get; }    // parent = existing vanilla node or another of ours
  IReadOnlyList<BuiltinDef> Builtins { get; }  // canonical snake_case name, neutral signature (for GameApi.Register),
                                               // tick cost, binding (pure or side-effect), granted by which unlock
  void OnFarmCreated(FarmContext ctx);         // timers, per-save state load
  void SaveState(JsonObject o); void LoadState(JsonObject o);
}
static class ExtensionRegistry { All; bool IsEnabled(id); void SetEnabled(id, bool) /*persists in BepInEx config*/; }
```
- Items: injected in a prefix on `StringIds.SetItemIds` (always, so the item count never changes), `enabled` follows
  the toggle, icons from PNGs in content/extensions/<id>/icons (fallback: tinted copy of a vanilla icon).
- Unlocks: UnlockSO instances added in a `ResourceManager.LoadAll` postfix; `mesh = null`, `displayCode` per language
  (generated: the canonical Python snippet → current language printer), names lowercase, no trailing _digits,
  hung under an existing vanilla node. Disabled → removed from the dictionary before `ResearchMenu.Setup`.
- Builtins: added to/removed from `BuiltinFunctions.Functions`; registered with the compiler via
  `GameApi.Register` so every language sees them with its naming convention (camelCase/PascalCase/snake_case) and
  type-checks them. Farm-touching builtins use custom side effects `(SideEffect)1000+k` through the existing
  `Execution.ApplySideEffect` prefix. Gated by putting their names in the granting unlock's `unlocks` list.
- **API shape rule (so all 9 languages can use them, including C and Zig):** extension builtins take and return only
  numbers, booleans and strings (plus List<float>/List<String> where unavoidable). No tuples/objects; prefer
  accessor style (`log_count()`, `log_ip(i)` …).
- Docs: canonical pages in Python under content/python/docs/mods/<id>/*.md (index + one page per unlock), real
  educational content (concept, why it matters in real security/ML, a worked example, exercises). Per-language
  copies are generated by the DocsTranslator (code blocks → each language). home.md gets a "Mods" section gated with
  `<unlock=…>`. Tooltips: `@code_tooltip_<name>` per language (generated the same way).
- Strings: `content/<lang>/Strings/extensions.txt` (generated) for unlock titles/descriptions, item descriptions.
- Deterministic randomness: per-save seed in the sidecar, so puzzles are reproducible and `simulate()` stays sane.

## 3. Cybersecurity extension (id `cybersecurity`, currency item **Bits**)
Root `cybersecurity` hangs under vanilla `lists` (needs lists/loops/functions knowledge). Each unlock opens a doc page.
Costs: vanilla items for the root, then Bits (+ some vanilla items) for the rest.
| unlock | teaches | builtins (snake_case canonical) | loop |
|---|---|---|---|
| cybersecurity | brute force & password length | `vault_pin_length()`, `vault_try(pin)` → bool (200 ticks: rate limiting) | correct PIN → Bits = 10^len/…; new PIN. Levels 1–3 raise PIN length (exponential cost lesson) |
| side_channels | timing/oracle leaks | `vault_check_digit(i, d)` → bool (1 tick) | crack in 10·n instead of 10^n; explains why constant-time compare matters |
| cryptography | Caesar → Vigenère → frequency analysis (levels) | `intercept()` → string, `decrypt_submit(text)` → bool, `char_code(s, i)` → number, `from_char_code(n)` → string | messages are farm instructions; correct plaintext → Bits |
| hashing | hashes, dictionary attacks, salts (level 2) | `hash_text(s)` → number (deterministic, documented algorithm), `leaked_hash_count()`, `leaked_hash(i)`, `leaked_salt(i)`, `wordlist_size()`, `wordlist_word(i)`, `crack_submit(i, password)` → bool | cracked entries → Bits |
| intrusion_detection | log analysis, thresholds, false positives | `log_count()`, `log_ip(i)`, `log_user(i)`, `log_success(i)`, `block_ip(ip)` → bool | blocking the real attacker → Bits; blocking a legit user costs Bits |
| firewall | rule-based filtering | `packet_next()` → bool (is there one), `packet_port()`, `packet_src()`, `packet_size()`, `packet_allow()`, `packet_deny()` | score per batch → Bits |
| secure_farm (capstone, levels) | defense in depth | — | permanent yield bonus for all crops (+5 %/level), shown in tooltip |

## 4. AI / ML extension (id `ai_ml`, currency item **Insight**)
Root `machine_learning` hangs under vanilla `utilities` (needs min/max/abs). Same structure.
| unlock | teaches | builtins | loop |
|---|---|---|---|
| machine_learning | datasets, mean, error | `sample_count()`, `sample_x(i)`, `sample_y(i)`, `new_dataset()` | intro: predict the mean, `submit_prediction(v)` → number (error) |
| linear_regression | least squares / gradient descent | `submit_line(slope, intercept)` → number (R²) | dataset = crop yield vs water; reward Insight ∝ R² above threshold |
| classification | perceptron, accuracy | `point_count()`, `point_x(i)`, `point_y(i)`, `point_label(i)` (+1/−1), `submit_classifier(w_x, w_y, bias)` → accuracy | weeds vs crops |
| clustering | k-means | `cluster_k()`, `submit_centroid(j, x, y)`, `evaluate_clusters()` → inertia score | assign drones to field regions |
| neural_networks | forward pass, weights, XOR | `nn_submit_weight(layer, i, j, w)`, `nn_submit_bias(layer, j, b)`, `nn_evaluate()` → accuracy | 2-2-1 net must solve XOR |
| reinforcement_learning | Q-learning | `env_reset()` → state, `env_state()`, `env_actions()`, `env_step(a)` → reward, `env_done()` → bool, `submit_policy_action(state, a)`, `evaluate_policy()` → score | tiny grid world |
| smart_farm (capstone, levels) | AI-assisted farming | — | permanent growth-speed or yield bonus (+5 %/level) |
Numbers in datasets are generated from the per-save seed; scoring formulas are documented on the pages.

## 5. Acceptance
- Headless unit tests for every builtin (binding logic, scoring, determinism, side-effect handling) and for save
  sidecar round trips; Harmony patch target signatures checked by reflection tests (as PatchTests.cs does today).
- In-game (Wine container, screenshots): Mods button visible on title + pause menu, panel works, toggling on shows the
  new tree branch and items, a sample solution program (in at least Python and Java) earns the currency, toggling off
  hides everything and the save still loads, toggling on restores progress.


## 6. As built (extensions work)

### Framework (src/JavaFarmer.Plugin/Extensions/)
- `ExtensionBootstrap.RegisterAll(Harmony harmony, string contentRoot)` (partial class; also `RegisterAll(harmony)`, `RegisterAll()`):
  registers Cybersecurity + AI / ML with `ExtensionRegistry` and applies the extension's own patch list
  (`ExtensionPatches.All()`, 12 patches, failures are logged and skipped). `ExtensionBootstrap.CurrentLanguage` (Func<string>)
  tells docs/tooltips/unlock boxes which language to show. Call after `ExtensionRegistry.Init(Config)`.
- `ContentExtension : IExtension` (Model.cs): `Items` (ItemDef), `Unlocks` (UnlockDef: name, parent, order, docs, Python
  display code, levels, costs, grants, capstone bonus), `Builtins` (BuiltinDef: canonical name, neutral GameApi signature, return
  type, tick cost, pure flag, `Func<ExtCall, object> Impl`), `NewState(seed)`. A builtin's logic only sees `ExtCall`
  (validated args, per-save `ExtState`, `Level(unlock)`, `Grant/Take(item, n)`); errors are `ExtError` → `ExecuteException`.
- `ExtensionHost`: item injection in the `StringIds.SetItemIds` prefix (always, `trackStats = false`, `enabled` follows the toggle,
  priorities 200000+ so vanilla ids never move); UnlockSOs created in the `ResourceManager.LoadAll` postfix; `Sync()` (LoadAll
  postfix and `Saver.Load` prefix) puts unlocks into / removes them from `ResourceManager.unlocks`, builtins into / out of
  `BuiltinFunctions.Functions` and `GameApi.Register/Unregister`, translates the unlock-box code, nulls `TooltipUtils.keywordDocs`
  and merges / removes the extension strings. Toggles apply on the next scene load (the Mods menu saves and reloads).
- Builtins: pure ones (`char_code`, `hash_text`, `nn_sigmoid` …) return in the binding; all others set
  `(SideEffect)(1000 + extension index)` with an `ExtensionHost.PendingCall` in `currentSideEffectArgument2`, and the
  `Execution.ApplySideEffect` prefix (Priority.First) runs them under lockSimulation, sets ReturnValue and adds the ticks.
- Per-save state: `SaveSidecar.Sections["cybersecurity" | "ai_ml"]` = `{"format":1,"items":{…mirror of the currency…},"state":{"seed":…}}`,
  written on `SaveSidecar.Saving`, read on `SaveSidecar.Loaded` (fallback: `Saver.Load` postfix). Puzzles are regenerated from
  (per-save seed, puzzle kind, counter) with `ExtRandom` (SplitMix64), so a reload continues every puzzle exactly. `simulate()` and
  leaderboard runs get a copy of the state. The item mirror restores currency the game dropped (save opened without the plugin).
- Capstones: `secure_farm` +5 %/level on harvest yields (`Farm.CollectItems` prefix during `Drone.Harvest`, whole items, fractions
  carried), `smart_farm` grow time / (1 + 0.05·level) (`Growable.GetGrowTime` postfix). Tooltip shows "now => next".
- Content: canonical Python pages in content/python/docs/mods/<id>/, strings in content/python/Strings/extensions*.txt
  (`extensions.txt`: unlock titles/descriptions, item descriptions, bonus lines; `extensions_code_tooltips_<id>.txt`),
  icons in content/extensions/<id>/icons/. Pages / strings are served only while the extension is enabled, translated with
  DocsTranslator (spans a language cannot print stay Python). docs/home.md gets a "Mods" section with the enabled extensions.
- Tests: tests/JavaFarmer.Plugin.Tests/Extensions/ (logic, binding, side effects, state round trip, toggles, Harmony targets,
  game-parser oracle, every worked example executed headless by the real game interpreter, docs/strings translation for every
  language in `Languages.All` with tolerated limits in Extensions/docs-exceptions.txt).

### Cybersecurity (currency `Items.Bits`)
Tree: `cybersecurity` (under `lists`, 3 levels: PIN length 2/3/4) → `side_channels` → `intrusion_detection` (2) → `firewall` (3) →
`secure_farm` (5, capstone); `cybersecurity` → `cryptography` (3: Caesar / Vigenère 2-3 / Vigenère 4-6) → `hashing` (2: unsalted / salted).
Costs: root {pumpkin 2000, carrot 2000}, then 5000 / 20000 Bits; side_channels 1500; cryptography 50k/100k/200k; hashing 150k/400k;
intrusion_detection 300k/800k; firewall 600k/1.5M/3M; secure_farm {1M Bits, 5000 gold}, {1.5M, 7500}, ×1.5 per level.
Rewards: vault 5·n² Bits; cipher 1000/3000/15000; hash 40/400 per entry; attacker blocked 150/200 (legit blocked −100/−150);
firewall batch score (+3/+2/−6/−3 per packet) ×3/×5/×8.

| builtin (canonical) | returns | ticks | unlock | meaning |
|---|---|---|---|---|
| `vault_pin_length()` | int | 1 | cybersecurity | Number of digits of the vault PIN. |
| `vault_try(pin: int)` | bool | 200 | cybersecurity | Tries a PIN on the vault; True and Bits if it was right (a new PIN is set). |
| `vault_check_digit(i: int, d: int)` | bool | 25 | side_channels | Timing leak: True if digit i (0 = leftmost) of the PIN is d. |
| `intercept_message()` | string | 1 | cryptography | The intercepted encrypted message. |
| `cipher_key_length()` | int | 1 | cryptography | Length of the key of the intercepted message (1 = Caesar). |
| `decrypt_submit(text: string)` | bool | 200 | cryptography | Submits the decrypted message; True and Bits if it is right (a new message arrives). |
| `char_code(s: string, i: int)` | int | 1 | cryptography | Character code of s[i] (A = 65, a = 97, space = 32). |
| `from_char_code(n: int)` | string | 1 | cryptography | The one-character string with character code n (65 = A). |
| `hash_text(s: string)` | int | 5 | hashing | Hash of a text: h = (h * 31 + char_code) % 1000000007 over its characters. |
| `leaked_hash_count()` | int | 1 | hashing | Number of entries in the leaked password database. |
| `leaked_hash(i: int)` | int | 1 | hashing | Stored hash of entry i. |
| `leaked_salt(i: int)` | string | 1 | hashing | Salt of entry i (empty without salts). |
| `wordlist_size()` | int | 1 | hashing | Number of words in the attacker's wordlist. |
| `wordlist_word(i: int)` | string | 1 | hashing | Word i of the wordlist. |
| `crack_submit(i: int, password: string)` | bool | 200 | hashing | Submits the password of entry i; True and Bits if it matches the hash. |
| `log_count()` | int | 1 | intrusion_detection | Number of entries in the login log. |
| `log_ip(i: int)` | string | 1 | intrusion_detection | Source address of log entry i. |
| `log_user(i: int)` | string | 1 | intrusion_detection | Account name of log entry i. |
| `log_success(i: int)` | bool | 1 | intrusion_detection | True if the login of entry i succeeded. |
| `block_ip(ip: string)` | bool | 200 | intrusion_detection | Blocks an address: True and Bits for an attacker, False (and a Bits penalty) for a legit user. |
| `log_next()` | void | 200 | intrusion_detection | Archives the current log and starts the next one. |
| `packet_next()` | bool | 10 | firewall | Moves to the next packet; False at the end of a batch (the batch is scored, a new one starts). |
| `packet_port()` | int | 1 | firewall | Destination port of the current packet. |
| `packet_src()` | string | 1 | firewall | Source address of the current packet. |
| `packet_size()` | int | 1 | firewall | Size of the current packet in bytes. |
| `packet_allow()` | void | 10 | firewall | Lets the current packet through. |
| `packet_deny()` | void | 10 | firewall | Drops the current packet. |

### AI / ML (currency `Items.Insight`)
Tree: `machine_learning` (under `utilities`) → `linear_regression` → `classification` → `neural_networks` → `smart_farm` (5, capstone);
`machine_learning` → `clustering` → `reinforcement_learning`.
Costs: root {pumpkin 3000, carrot 3000}; linear_regression 20k; clustering 25k; classification 60k; reinforcement_learning 100k;
neural_networks 150k Insight; smart_farm {1M Insight, 5000 gold}, {1.5M, 7500}, ×1.5.
Reward = floor(Base · q^Power), q ∈ [0, 1]: mean (Base 10, q = best MSE / MSE, ^4), line (40, R²/R²ols, ^8), classifier
(800, (acc−0.5)/0.5, ^4), k-means (1200, reference inertia / inertia, ^4), XOR net (300, (acc−0.5)/0.5, ^4; tasks drift slightly so
fine-tuning works), Q-learning policy (8000, (score+50)/(optimal+50), ^4).

| builtin (canonical) | returns | ticks | unlock | meaning |
|---|---|---|---|---|
| `sample_count()` | int | 1 | machine_learning | Number of samples in the current dataset. |
| `sample_x(i: int)` | float | 1 | machine_learning | Feature x of sample i (water given to the plot). |
| `sample_y(i: int)` | float | 1 | machine_learning | Target y of sample i (the plot's yield). |
| `new_dataset()` | void | 200 | machine_learning | Discards the current dataset and loads the next one. |
| `submit_prediction(value: float)` | float | 200 | machine_learning | Predicts value for every sample; returns the mean squared error and loads the next dataset. |
| `submit_line(slope: float, intercept: float)` | float | 200 | linear_regression | Predicts y = slope * x + intercept; returns R² and loads the next dataset. |
| `point_count()` | int | 1 | classification | Number of labelled training points. |
| `point_x(i: int)` | float | 1 | classification | x of training point i. |
| `point_y(i: int)` | float | 1 | classification | y of training point i. |
| `point_label(i: int)` | int | 1 | classification | Label of training point i: 1 = crop, -1 = weed. |
| `submit_classifier(w_x: float, w_y: float, bias: float)` | float | 200 | classification | Classifies hidden test points with w_x * x + w_y * y + bias >= 0; returns the accuracy and loads the next dataset. |
| `cluster_k()` | int | 1 | clustering | Number of clusters (drones) for the current field. |
| `cluster_point_count()` | int | 1 | clustering | Number of points to cluster. |
| `cluster_point_x(i: int)` | float | 1 | clustering | x of point i. |
| `cluster_point_y(i: int)` | float | 1 | clustering | y of point i. |
| `submit_centroid(j: int, x: float, y: float)` | void | 1 | clustering | Places centroid j (0 to cluster_k() - 1) at (x, y). |
| `evaluate_clusters()` | float | 200 | clustering | Scores the centroids: returns the inertia (sum of squared distances to the nearest centroid) and loads the next field. |
| `env_reset()` | int | 1 | reinforcement_learning | Starts a new episode; returns the start state. |
| `env_state()` | int | 1 | reinforcement_learning | Current state (y * 5 + x). |
| `env_state_count()` | int | 1 | reinforcement_learning | Number of states (25). |
| `env_actions()` | int | 1 | reinforcement_learning | Number of actions (4: 0 North, 1 East, 2 South, 3 West). |
| `env_step(a: int)` | float | 1 | reinforcement_learning | Takes action a; returns the reward of the step. |
| `env_done()` | bool | 1 | reinforcement_learning | True if the episode is over. |
| `submit_policy_action(state: int, a: int)` | void | 1 | reinforcement_learning | Sets the action of the policy in a state. |
| `evaluate_policy()` | float | 200 | reinforcement_learning | Scores the policy: returns its average return and starts a new world. |
| `nn_point_count()` | int | 1 | neural_networks | Number of training points of the XOR task. |
| `nn_point_x(i: int)` | float | 1 | neural_networks | x of training point i. |
| `nn_point_y(i: int)` | float | 1 | neural_networks | y of training point i. |
| `nn_point_label(i: int)` | int | 1 | neural_networks | Label (0 or 1) of training point i. |
| `nn_sigmoid(x: float)` | float | 1 | neural_networks | The logistic function 1 / (1 + e^-x). |
| `nn_submit_weight(layer: int, i: int, j: int, w: float)` | void | 1 | neural_networks | Sets a weight: layer 0 = input i (0 = x, 1 = y) to hidden j, layer 1 = hidden i to the output (j = 0). |
| `nn_submit_bias(layer: int, j: int, b: float)` | void | 1 | neural_networks | Sets a bias: layer 0 = hidden unit j, layer 1 = the output (j = 0). |
| `nn_output(x: float, y: float)` | float | 5 | neural_networks | Output (0 to 1) of the network for the input (x, y). |
| `nn_evaluate()` | float | 200 | neural_networks | Scores the network on hidden test points: returns the accuracy and loads the next task (the weights stay). |
